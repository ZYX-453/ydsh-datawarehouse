# 企业数仓第一周：环境搭建与 ODS-DWD 链路贯通

**周期**：2026.10.24 – 2026.10.30 ｜ **项目**：云购生活新零售企业级数据仓库 ｜ **角色**：一人多岗（独立交付）

## 一、本周工作概述

本周聚焦企业数据仓库项目（仓库名 `ydsh-datawarehouse`）第一周交付，核心完成了从零搭建到首条数据链路上线的全链路工作，共形成 7 项交付物、18 次 Git 提交，并已打包 `第1周_张宇翔.zip` 待上传教学平台。

## 二、关键成果

1. **环境搭建与版本控制**。基于 Docker Desktop 部署 Hive 4.0（Tez 引擎）+ MySQL 元数据库，并彻底解决 Git Bash（MSYS）环境下的四类路径陷阱——Unix 路径不被 Docker 识别、`echo -e` 吞掉转义符、伪终端 stdin 重定向拿空内容、MSYS 参数自动改写容器路径。`run_all.sh` 经四轮修复后稳定跑通。同时创建 GitHub 远程仓库、配置 443 备用 SSH 通道，累计推送 18 次提交，打通代码托管。

2. **数据链路贯通**。完成 ODS 贴源层建库、建表与导入（各表 1000/600/60/15600/37549/60000 条），定位并修复 Hive 元数据中文注释乱码（转 utf8mb4）；完成 DWD 明细层清洗（1000/15000 条），数据修复率 100%、重复率 3.85%。

3. **交付物齐备**。产出环境搭建笔记（含 11 个问题与运行状态截图）、数据质量预评估表（8 工作表 / 30 公式）、数据清洗说明、AI 协同日志（10 条协同记录，含 3 次方案被推翻的复盘）等 7 项交付物。

## 三、问题与复盘

最耗时的是 `run_all.sh` 的路径兼容问题，根因在于 Windows 下 Git Bash 的路径语义与 Docker 容器不一致。最终采用「宿主机目录挂载 + 容器内直接执行」方案，从源头消除文件传输环节，反而比 `docker cp` 更稳。这印证了「最小干预 + 直击根因」的排错思路。
